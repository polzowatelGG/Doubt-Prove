# Протокол эксперимента

## 1. Цель

Оценить, повышает ли структурированный AST/ABI-контекст и feedback loop качество автоматически генерируемых CVL-спецификаций.

## 2. Набор объектов

Минимум 10 контрактов в трёх группах:

1. учебные контракты: escrow, vault, bridge;
2. намеренно мутированные версии с 1–3 дефектами;
3. небольшие реальные open-source контракты с зафиксированной версией commit.

Для каждого объекта фиксируются:

- hash исходного файла;
- версия solc;
- версия Certora CLI/Prover;
- модель Ollama и параметры;
- hardware;
- seed/temperature;
- ручной gold-standard набор свойств.

## 3. Независимые переменные

- представление входа: raw source / AST+ABI;
- feedback loop: 0 или 3 итерации;
- размер модели;
- наличие few-shot примеров.

## 4. Зависимые переменные

- компилируемость CVL;
- семантическая корректность;
- обнаружение внедрённых дефектов;
- время и число токенов;
- ручное время исправления;
- вакуозность и ложные срабатывания.

## 5. Экспертная разметка

Каждый инвариант получает оценки 0/1:

- использует существующие сущности;
- соответствует бизнес-логике;
- проверяем в выбранной модели;
- не является тавтологией;
- не опирается на недостижимые предпосылки;
- способен отличить корректную версию от мутанта.

Желательно два независимых оценщика. Согласованность: Cohen’s kappa.

## 6. План

Для каждого контракта выполнить не менее пяти генераций в каждом режиме. Это снижает влияние случайности LLM. Результаты сохранить как неизменяемые JSON-артефакты.

## 7. Проверка мутациями

Создать дефекты:

- удалить проверку `processedWithdrawals[nonce]`;
- перенести effects после внешнего call;
- неверно обновить `totalLockedL1`;
- разрешить нулевой deposit;
- перепутать `+` и `-`;
- убрать проверку оператора.

Спецификация считается полезной, если корректная версия проходит, а соответствующий мутант нарушает хотя бы одно свойство.

## 8. Угрозы валидности

- выбор слишком простых контрактов;
- утечка эталонных спецификаций в prompt;
- зависимость от конкретной версии CVL;
- нестабильность облачного Prover;
- оценка одним экспертом;
- смешение ошибки контракта и ошибки модели окружения.
